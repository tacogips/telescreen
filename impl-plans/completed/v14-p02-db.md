## Intent and Context

Add the five data-inventory tables and the `collector_configs.inventory_mode` column.
This must follow the project DDL rule (AGENTS.md "Database Schema (DDL)"): the Nodetto
document is the source of truth and changes first, then the SQL exports are regenerated,
then the models change, then exactly one Alembic revision is added. The wave-2 plans
(p04, p05) and p07 write repositories against these models.

Agents cannot drive the Nodetto GUI, so edit the JSONL directly, following the shape of the
existing records:

- `erd.table`: see the element `t-issue-comments`;
- `erd.relation`: see `r-alert-fires-issue-id`;
- frame: see `f-issues-v13`.

Imitate:

- `db/models/issues_v13.py` (`Base, kw_only=True`, unannotated `__tablename__`, composite
  PKs, `Index(...)` in `__table_args__`);
- `db/migrations/versions/0004_v1_3.py` (the idempotent `NEW_TABLES` / `NEW_COLUMNS` /
  index tuples, table cloning via `to_metadata`, and a downgrade that uses
  `batch_alter_table` on SQLite);
- `db/migrations/versions/0001_initial.py` (the `audit_records` append-only trigger on
  PostgreSQL and the counter seed);
- `tests/db/test_v13_migration.py` and `tests/db/test_models.py`.

## Non-goals

- No repositories or services. No import of `telescreen.core.vocabulary` enums that p01
  adds in parallel: use string literals for defaults.
- Never edit `0001_initial.py` through `0004_v1_3.py`. Never edit `mise.toml`.

## Invariants

- `0005_v1_4`: `revision = "0005_v1_4"`, `down_revision = "0004_v1_3"`. It is idempotent:
  a second `upgrade head` is a no-op.
- `0001_initial` builds tables from the current metadata, so a fresh database already has
  the v1.4 schema. `0005` creates only what is missing.
- The Nodetto document, both SQL exports, the models and `alembic upgrade head` describe the
  same schema. Every new reference column is a logical relation. `*_ref` and `*_by` actor
  columns are not drawn.
- Every model file stays under 1000 lines.

## Pitfalls

- Index names in Nodetto must equal the model names exactly. The
  `tests/db/test_nodetto_schema.py` comparator also checks unnamed unique indexes against
  `unique=True`.
- `0002_v1_1`, `0003_v1_2` and `0004_v1_3` build some indexes from the current models. Run
  the existing downgrade/upgrade round-trip tests (`tests/db/test_v1*_migration.py`). If a
  historical revision now fails because of new v1.4 metadata, do not edit it: write a
  Reconciliation request with the failing test and the cause, as v13-p02 did.
- SQLite cannot add a NOT NULL column without a server default. The column has one, so
  plain `op.add_column` with `server_default` works.
- Do not draw relations for `created_by`, `updated_by` or `actor_ref`.
- `value_date` and `overdue_notified_for` are `varchar(10)` ISO dates, not DATE.
